SM Course Testing
Strategy 10 Lenses Feedback Fix Report

The 10 Testing Lenses

Every module is evaluated against 10 lenses. Two are common (applied by all teams with equal rigor). Eight are team-owned (2 per team — these teams go deeper and are the authoritative voice).

Common Lenses (all teams, equal depth)

L1

Content Accuracy

All teams
“Is what this module states factually correct — about Copilot, about Scrum, and about the Velocity Squad?”
CheckWhat to look for
Technical correctnessAre M365 Copilot features, UI elements, menu paths, and shortcuts described accurately? Do they match the current Copilot interface?
Scrum terminologyAre Scrum events (Sprint Planning, Daily Scrum, Sprint Review, Sprint Retrospective), artifacts, and roles named correctly per the Scrum Guide? No “standup” when meaning “Daily Scrum.”
Version currencyDo references match current Copilot capabilities (March 2026)? Are deprecated features or non-existent buttons referenced?
Data consistencyAre Velocity Squad metrics, sprint numbers, team member names, and project details (AKX, Horizon Program) consistent across all 27 modules?
Link & reference integrityDo cross-references to other modules, resource pages, and sample files resolve correctly? Do sample-files/... links work?
Terminology consistencyAre terms used consistently? (e.g., “Velocity Squad” not “velocity squad”, “Sprint 47” not “sprint 47”, team member names spelled consistently)

The SM course uses Scrum terminology extensively. Watch for mixing up Scrum Guide terms with casual alternatives (e.g., “sprint demo” instead of “Sprint Review”, “scrum meeting” instead of “Daily Scrum”). These errors undermine credibility with experienced SMs.

Reporting standard: Flag with exact quote and correction. Severity is always Major or Critical for factual errors. For Scrum terminology, cite the Scrum Guide section if relevant.
L2

Learner Clarity

All teams
“If I were an experienced Scrum Master encountering AI-augmented workflows for the first time, could I follow every step without guessing?”
CheckWhat to look for
Instruction precisionCan you complete each step exactly as written? Or did you have to interpret, infer, or Google? “Upload the file to Copilot” — which file, where, how?
Assumed knowledgeDoes the module assume Copilot familiarity it hasn’t taught yet? (SM expertise is assumed; AI expertise is not)
Ambiguous languageAre there phrases like “configure your context” or “set up your workflow” without specifying what that means?
Visual orientationWhen UI is referenced, is it clear where to look? Are nav paths like “Click the Copilot icon in the top-right” specific enough?
Cognitive signpostingAre transitions between concepts clear? Does the learner know why they’re doing each step, or is it “just do this”?
Jargon calibrationScrum jargon is fine (target audience knows it). AI/Copilot jargon must be introduced before use. “ContextIQ”, “grounding”, “chain-of-thought” need explanation.

The SM audience is technically sophisticated about Scrum but may be AI novices. The jargon calibration is inverted compared to the PM course: Scrum terms need no explanation, but AI concepts need careful introduction. Watch for modules that assume prompt engineering knowledge from Level 1.

Reporting standard: Quote the confusing passage, explain what tripped you up, suggest clearer wording. Rate confusion severity: “I paused” vs “I got stuck” vs “I couldn’t continue.”

Team-Owned Lenses

L3

Prompt Effectiveness

Team 1 — “Does it work?”
“When I copy this prompt into Copilot and run it with the provided context, does it produce output that would genuinely help a Scrum Master?”
CheckWhat to look for
Functional promptsCopy every prompt from the module into Copilot. Does it run without errors? Does it produce output matching what the module promises?
Output qualityIs Copilot’s response genuinely useful for the stated SM task, or is it generic filler? Does the impediment analysis actually categorize impediments, or just list them?
Prompt robustnessDoes the prompt work with slight variations (different team names, different sprint data)? Or is it brittle to the Velocity Squad context?
Prompt rationaleDoes the module explain why the prompt is structured that way? SMs need to adapt prompts to their own teams — understanding the structure matters more than memorizing it.
Context dependencyDo prompts that reference uploaded files (ceremony notes, metrics CSVs) work with the provided sample files? Are file references correct?
Multi-turn coherenceFor modules that build prompt chains (especially L2 and L6), does the conversation flow work? Does Copilot maintain context across steps?

The SM course has more complex prompts than the PM course — persona roleplay for conflict resolution (2.6), multi-step ceremony chains (6.1), meta-prompts that generate other prompts (2.5). Test these carefully; they’re more likely to produce inconsistent output.

Reporting standard: Include the exact prompt used, Copilot’s actual output (screenshot or paste), and what output was expected. For failed prompts, note whether the failure is the prompt’s design or Copilot’s limitation.
L4

Exercise Quality

Team 1 — “Does it work?”
“Are the hands-on activities well-designed, completable with provided materials, and genuinely building the SM skill the module claims to teach?”
CheckWhat to look for
CompletabilityCan you finish the exercise with the materials provided? Are sample files sufficient? Does the exercise work end-to-end without dead ends?
ScaffoldingDoes the exercise build progressively (guided → semi-guided → independent)? Or does it dump complexity at once?
Success criteriaIs it clear what “done well” looks like? Can the learner self-assess their output? Are “What You Should See” sections accurate?
Time realismDoes the exercise fit within the module’s stated duration? (Time yourself.) Modules claim 15-40 min — is that realistic including the exercises?
Learning alignmentDoes the exercise practice the skill the module claims to teach? A module about “predictive intelligence” (4.2) should have exercises that build early warning prompts, not just analyze past data.
Sample file qualityAre the 78 resource files (ceremony notes, metrics CSVs, conflict scenarios) realistic enough to produce meaningful Copilot output? Are CSVs well-formatted?

Pay special attention to exercises in Levels 4-6 (data-driven, scaling, AI-native). These are more advanced and may assume capabilities or context that earlier modules didn’t fully set up. Also test the conflict resolution roleplay exercises (2.6) — do the persona prompts produce psychologically realistic dialogue?

Reporting standard: Note which exercise, actual time taken vs stated, what was confusing or missing, and whether the exercise built the claimed skill.
L5

Instructional Design

Team 2 — “Does it teach?”
“Does this module teach effectively? Would I recommend this design to a client building training for their Scrum Masters?”
CheckWhat to look for
Learning objectivesAre objectives stated at the top? Are they measurable? Does the module content actually deliver on each stated objective?
Cognitive loadIs information density appropriate? ~13 hours is a lot — are there natural breathing spaces? Or is it a wall of prompts and exercises?
Retention hooksAre there summaries, key takeaways, “try this” moments, or reflection prompts? Do modules end with a clear sense of “what I learned”?
Multi-modal learningIs there a balance of reading, doing, and reflecting — or is every module the same format? Does the course leverage the Velocity Squad narrative as a learning device?
Assessment opportunityCan the learner check their own understanding before moving on? Are there self-assessment moments beyond “check your Copilot output”?
Module length calibrationAre 35-40 min modules too dense? Would any benefit from being split? Are 15 min modules too shallow to build real skill?

The PM course feedback revealed cognitive overload in several modules (6 of 170 findings). With the SM course being ~2x longer, this risk is amplified. Pay attention to Levels 2 and 4 specifically — they pack the most conceptual density into their modules.

Reporting standard: Reference specific learning objectives and whether the content delivers on each. For cognitive load issues, identify exactly where the overload hits.
L6

Progressive Flow

Team 2 — “Does it teach?”
“Does the 6-level arc feel like a genuine practitioner journey — from AI newcomer to AI-native Scrum Master? Or are the levels arbitrary groupings?”
CheckWhat to look for
Level-to-level arcDoes Foundation → Advanced → Visuals → Data-Driven → Scaling → AI-Native feel like a natural progression? Where does it feel forced?
Within-level sequencingWithin each level, do modules build on each other? Does 2.1 (Ceremonies) flow into 2.2 (Impediments) flow into 2.3 (Team Health)?
Prerequisite handlingWhen a module requires knowledge from an earlier one, is this stated or linked? Does 4.1 (Sprint Analytics) assume skills from 1.3 (First Tasks)?
Level 3 placementTeam Visuals (DALL-E) sits between Advanced SM Workflows and Data-Driven. Does this feel like the right position, or does it break the analytical flow?
Repetition vs reinforcementIs repeated content (e.g., how to upload files to Copilot) intentional reinforcement or accidental redundancy?
Completion arcDoes Module 6.3 (Building Your AI-Augmented SM Practice) feel like a satisfying culmination? Does the learner know what to do next?

This lens is critical for the SM course. With 6 levels (vs PM’s 3), the progression design is harder to get right. Key question: does a Level 1 completer have enough to be immediately useful? Or does the real value only appear at Level 4+? The course should deliver value at every level break.

Reporting standard: Map dependency/flow issues across modules. This lens is inherently cross-module. Diagram the actual learning dependency graph vs the stated sequence.
L7

Scrum Fidelity & Coaching Depth

Team 3 — “Does it develop practitioners?”
“Does this course represent Scrum correctly, and does it develop actual coaching and facilitation skills — or does it just teach people to paste prompts into Copilot?”
CheckWhat to look for
Scrum Guide alignmentAre Scrum events, artifacts, and accountabilities represented accurately? Does the course inadvertently promote anti-patterns (e.g., SM as project manager)?
Coaching vs tool usageDoes the course develop the SM’s judgment about when and how to use AI, or does it reduce the role to “run this prompt”? The SM role is fundamentally about human interaction.
Facilitation realismDo ceremony facilitation modules (2.1) acknowledge that real facilitation involves reading the room, adapting on the fly, and managing energy — not just generating agendas?
Coaching scenario depthAre conflict resolution scenarios (2.6) and coaching conversations (2.3) psychologically realistic? Do they capture the nuance of real team dynamics?
AI augmentation framingIs AI positioned as augmenting SM skills (preparation, analysis, reflection) rather than replacing them (automated decision-making, skip-the-conversation shortcuts)?
Velocity Squad authenticityDoes the Velocity Squad (7-person team, Sprint 47, AKX project) feel like a real Scrum team? Are their challenges, dynamics, and maturity level believable?

This is the lens that didn’t exist in the PM course. The PM course tested “Enterprise Realism” — is the Accenture scenario believable? The SM course needs something deeper: does the course develop practitioner capability or just tool proficiency? An SM who completes this course should be a better SM, not just faster at generating documents.

Reporting standard: Draw on your own SM/coaching experience. Flag where the course promotes AI over judgment, or where facilitation is oversimplified. Rate: “This builds real SM skill” vs “This just teaches a Copilot trick.”
L8

Practitioner Applicability

Team 3 — “Does it develop practitioners?”
“Could a Scrum Master take what they learned here and apply it with their team next Monday — regardless of their team’s maturity, industry, or scale?”
CheckWhat to look for
Transferable techniquesAre prompts and frameworks taught in a way that generalizes beyond the Velocity Squad? Can they adapt to a 3-person startup team or a 12-person enterprise team?
Immediate usefulnessAfter completing a module, could you use that technique in your current engagement this sprint? Or does it require setup, approval, or context that takes weeks?
Team maturity sensitivityDo techniques work for both new-to-Scrum teams and mature teams? Does the course acknowledge that a team in Sprint 3 needs different AI support than a team in Sprint 47?
Template extractabilityCan prompts, cheat sheets, and frameworks be copied and adapted for real projects? Are the prompt library and cheat sheets genuinely useful as standalone references?
Environment dependencyDoes the skill work only with specific M365 configurations, or across typical enterprise setups? Are Copilot license assumptions stated?
Scaling validityDo Level 5 multi-team scenarios (Horizon Program, 3 teams) represent realistic scaling challenges? Would an RTE find them useful?
Reporting standard: For each module, rate “I could use this next sprint” on a 1-5 scale with explanation. Note which techniques are immediately portable vs require significant adaptation.
L9

Platform & Interactive Features

Team 4 — “Does it deliver?”
“Does the course platform enhance learning, or does it get in the way? Do all 14 interactive features work correctly?”
CheckWhat to look for
Copy-to-clipboardDo copy buttons appear on all code/prompt blocks? Does clicking “Copy” put the correct text in the clipboard? Does “Copied!” feedback appear? Test on different browsers.
Table of ContentsDoes the TOC sidebar appear on module pages? Does scroll-spy highlight the current section? Does clicking a TOC item scroll to the right place?
Reading progress barDoes the thin bar at the top track scroll position accurately? Does it reach 100% at the bottom?
Progress trackingDoes “Mark as Complete” work? Does completion persist across browser sessions? Does the index page show the correct completion percentage?
Dark modeDoes the toggle work? Are all elements readable in dark mode (tables, callouts, code blocks, exercise cards)? Does preference persist?
Keyboard navigationDo left/right arrow keys navigate between modules? Does Escape go to the index? Do these shortcuts not interfere with text selection or scrolling?
Mobile experienceDoes the hamburger menu work? Is the mobile TOC collapsible? Are prompts readable and copy-able on phone screens? Test on actual mobile devices.
Level colorsDo all 6 levels have distinct accent colors? Are they applied consistently to badges, headers, nav buttons, and exercise cards?
Print outputDoes Ctrl+P produce a clean, single-column layout without nav chrome, copy buttons, or TOC? Is it usable as a reference printout?
CSV renderingDo the metrics CSV files (velocity history, burndown, health surveys) render as readable HTML tables? Are headers correct?
Exercise cards & calloutsAre exercises visually distinct with card styling? Do callout boxes (tip, warning, reference) render with correct icons and colors?
Cross-browserTest Chrome, Edge, Firefox, Safari. Test file:// protocol (open HTML directly from filesystem).

The SM course static site has 14 interactive features that the PM course didn’t have. This means L9 has significantly more surface area to test. Allocate extra time for this lens. Enterprise SMs often work on locked-down machines — test that nothing requires admin privileges or external CDN access beyond Google Fonts.

Reporting standard: Include browser + version, device, protocol (http vs file://), screenshot of the issue, and steps to reproduce. For dark mode issues, include both light and dark screenshots.
L10

Gaps & Completeness

Team 4 — “Does it deliver?”
“What question would a Scrum Master have that this course doesn’t answer? What SM skill is missing from the 6-level journey?”
CheckWhat to look for
Missing SM workflowsAre there critical SM tasks with Copilot that should be covered but aren’t? (e.g., backlog refinement facilitation, Definition of Done workshops, release planning)
Unanswered questionsAt any point, did you think “but what about...?” and the course never addressed it? Track these moment by moment.
Audience blind spotsDoes the course assume a specific SM profile (e.g., single-team SM at an enterprise)? Does it miss new SMs, RTEs, freelance coaches, or SMs in non-tech industries?
Copilot limitations honestyDoes the course acknowledge where Copilot falls short for SM tasks? Or does it only show the happy path? Are data privacy concerns for team health data addressed?
Level 4-6 sufficiencyAre the advanced levels (Data-Driven, Scaling, AI-Native) deep enough to be useful to experienced practitioners? Or do they skim the surface of complex topics?
Resource completenessAre all 78 resource files referenced from relevant modules? Are there orphan resources nobody points to? Are there module references to files that don’t exist?
Post-course pathAfter completing all 27 modules, does the learner know what to do next? Is there a clear “you’re ready to...” statement?
Reporting standard: Frame each gap as “A Scrum Master would expect to find [X] but the course doesn’t cover it because [Y is missing].” Distinguish “nice to have” from “this gap undermines the course promise.”

How “Focus More, Not Only” Works

Every tester applies all 10 lenses while going through each module. The difference:

Lens TypeWhat You DoFeedback Expectation
Common lenses (L1, L2)Full attention, equal across all teamsFlag every issue you find
Your team’s owned lensesDeep, deliberate focus — this is your primary jobDetailed findings with evidence; you are the authority
Other teams’ owned lensesNotice in passing while going through the moduleFlag only obvious/glaring issues; don’t go hunting

This means each module gets:

4x coverage

Common lenses
(all teams)

1x deep

Each owned lens pair
(assigned team)

3x light

Each owned lens pair
