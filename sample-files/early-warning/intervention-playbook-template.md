# Early Warning Intervention Playbook

## How to Use This Template

For each early warning signal, define: what triggers it, what to do immediately, when to escalate, and how to know if your intervention worked.

---

## Signal 1: Multiple Team Members Blocked on Same Resource

| Field | Details |
|-------|---------|
| **Trigger** | 2+ team members blocked on same person/system for 24+ hours |
| **Data Source** | Daily standup notes, impediment log |
| **Severity** | High — compounds daily |
| **First Response (within 4 hours)** | Direct conversation with blocking resource. Understand timeline. Can we unblock partially? |
| **If Not Resolved (24 hours)** | Re-plan sprint: swap blocked stories for unblocked ones from backlog. Alert PO to potential scope change. |
| **Escalation Trigger** | Resource unavailable for 48+ hours AND >25% of sprint at risk |
| **Escalation Path** | SM → Jennifer Walsh (VP) with data: X points blocked, Y days impact, Z cost |
| **Success Metric** | Blocked time < 48 hours. Sprint goal still achievable after re-plan. |
| **Failure Mode** | Waiting passively. "David said Monday" is not a plan — it's hope. |

## Signal 2: Velocity Trending Down (3+ Sprints)

| Field | Details |
|-------|---------|
| **Trigger** | Velocity below mean for 3 consecutive sprints |
| **Data Source** | Velocity history chart, control limits |
| **Severity** | Medium — systemic, not acute |
| **First Response (within 1 sprint)** | Root cause analysis: is this capacity (someone left?), complexity (harder work?), or health (team struggling?) |
| **If Not Resolved (2 sprints)** | Dedicated retrospective on velocity. Bring data. Ask team to diagnose. |
| **Escalation Trigger** | Velocity below LCL (lower control limit) for any sprint |
| **Escalation Path** | SM → team first, then management with action plan |
| **Success Metric** | Velocity returns to within control limits within 2 sprints |
| **Failure Mode** | Pressuring team to "work harder." Velocity is an output, not an input. |

## Signal 3: Health Score Declining

| Field | Details |
|-------|---------|
| **Trigger** | Any health dimension drops 0.5+ points sprint-over-sprint |
| **Data Source** | Sprint health survey |
| **Severity** | High — health predicts velocity 2-3 sprints ahead |
| **First Response (within 1 week)** | 1:1 conversations with team members. Explore root cause. |
| **If Not Resolved (1 sprint)** | Targeted retrospective on the declining dimension. |
| **Escalation Trigger** | Morale below 2.5/5 OR Trust below 3.0/5 |
| **Escalation Path** | SM → individual coaching first, then team intervention, then management if systemic |
| **Success Metric** | Declining dimension stabilizes or improves within 2 sprints |
| **Failure Mode** | Ignoring the data. "It's just a survey." Health surveys are the team's voice. |

## Signal 4: Standup Duration Creeping

| Field | Details |
|-------|---------|
| **Trigger** | Average standup exceeds 20 minutes for 3+ consecutive days |
| **Data Source** | Meeting duration tracking, observation |
| **Severity** | Low-Medium — indicates unclear focus or unresolved blockers |
| **First Response (next standup)** | Observe: is it one person talking too long, or everyone? Redirect to "blockers only" format. |
| **If Not Resolved (1 week)** | Standup format reset. Introduce parking lot for deep-dive topics. |
| **Escalation Trigger** | Standup regularly exceeds 25 minutes AND team is frustrated |
| **Escalation Path** | No escalation needed — this is SM's domain to fix |
| **Success Metric** | Standup returns to <15 minutes within 1 week |
| **Failure Mode** | Cutting people off without addressing WHY they're talking longer. |

---

## Signal 5: Retro Actions Not Getting Done

| Field | Details |
|-------|---------|
| **Trigger** | <50% of retro actions completed before next retrospective |
| **Data Source** | Action item tracking |
| **Severity** | Medium — erodes trust in improvement process |
| **First Response (mid-sprint)** | Check in on action owners. Remove blockers. Re-prioritize if needed. |
| **If Not Resolved (2 sprints)** | Reduce number of retro actions (fewer, more impactful). Assign owners AND due dates. |
| **Escalation Trigger** | <25% completion rate for 3+ sprints (team has given up on retros) |
| **Escalation Path** | SM → team conversation about retro value. Consider format change. |
| **Success Metric** | >75% completion rate sustained for 3 sprints |
| **Failure Mode** | Adding more actions. The problem is completion, not identification. |
